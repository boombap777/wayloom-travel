# 旅行草案单页设计

目标：一分钟展示“自然语言需求—缺失信息追问—受限目录—旅行草案”。
不新增复杂前端框架；使用原生 HTML/CSS/JavaScript、本机 Python HTTP API 和原有规划器。

浅色灰绿背景、暖白卡片、单一绿色主按钮；桌面双列（输入/需求小结），窄屏单列。
进度只有三个阶段，依据真实返回更新；加载只显示等待状态，不伪造 Agent 推理过程。
结果区按需出现，JSON/工具详情折叠；正文展示来源、样例预算和活动大纲，不假装实时产品。

正常、补全、无匹配、错误、忙碌、重新开始六类状态必须可见。所有动态文本使用
textContent，不渲染模型 HTML；API 只接受受限用户消息，不接受工具调用或模型路径。
模型模式由服务端启动参数显式选择，默认 rule 诚实标注。当前不增加登录、永久记忆、
实时预订、地图或支付能力；这些不属于校招原型的最小界面。
